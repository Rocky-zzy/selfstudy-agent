## 一、这一步要回答什么

> **"讲解方式优化"这个杠杆，在本项目上到底成不成立？**

可证伪点（`docs/00` §四）：如果两个条件给出的讲解，用户在实测中读不出差别，
那么这个杠杆在这一层就不成立，应该把精力挪到别的层（L0 结构 / L2 决策）。

## 二、基线定义（用户 2026-09-17 确认；2026-09-26 加第三个条件后更正）

| 条件 | 定义 |
|---|---|
| **raw**（2026-09-26 新增） | 同款 LLM + 同一批课件原文 + 问题。**零约束**——system prompt 只有一句"请回答他的问题" |
| **baseline** | 同款 LLM + 同一份原文 + **共用块**（范围 + 输出格式 + 术语加注 + 教学骨架 + 讲法档） |
| **optimized** | 同款 LLM + 同一份原文 + 同上共用块 + **`docs/03` §六 的 4 条讲解方式约束** |

**为什么要"直灌整页/整讲"而不是摘要**：这样各条件之间，**唯一变量就是系统指令**。
一旦我们在检索或摘要上做手脚，差异就无法归因。

**三个条件严格共用的东西**：检索器、课件原文的选页与拼接、模型、temperature(0.3)、
max_tokens(4000)。→ 唯一差异是 system prompt。

`APP_STRIP_OPT=1` 可以把那 4 条关掉（optimized 退化成 baseline），
用来自查"读出的差异是不是真来自这几条约束"。

### ★ 更正（用户 2026-09-26 指出）：以前把 baseline 说成"冷启动"是错的

**用户原话**：「我认为范围约束 + 输出格式约束 + 术语加注 + 教学骨架 + 知识结构图
以及 docs/03 §六 的 4 条讲解方式约束**都是我们做的优化**呀。」

**他是对的。** baseline 也带着我们的优化（范围、格式、术语、骨架、图谱），
它**不是**冷启动。于是两个不同的问题被混成了一个：

| 想回答的问题 | 该拿谁比 | 状态 |
|---|---|---|
| 那 **4 条约束**有没有用 | optimized vs baseline | ✅ r1–r4 一直在测（r4：+0.15） |
| **我们的优化**比裸模型好多少 | optimized vs **raw** | ✅ **2026-09-26 补跑，见 `docs/12` §六** |

**所以下面那段措辞纪律要改**（保留原文以留痕）：
- ❌ 旧的（过度保守）：「本阶段结论**不得**表述为"优于同款 LLM 冷启动"」
- ✅ 新的：**"优于同款 LLM 冷启动"现在可以说了**，依据是 `docs/12` §六 的
  optimized vs raw（编码 3：1.25 → 2.65；High 10% → 65%；逐问 17 胜 0 负 3 平）。
  但**必须带上限定**：n=1 用户、单一盲评判者、MQI 的 segment 映射是本项目自定的、未验证。

⚠️ 仍然**不能**把 baseline 的分数当成"裸 LLM 的分数"——两者不是一回事。

### （原记录，措辞纪律部分已被上节更正）

定调里写的是"优于**同款 LLM 冷启动**"。严格意义上，那需要一个**完全没有约束**的基线。

**当时这两个条件都带范围约束**（只回答所问、不分章节）。
也就是说，**那时的基线不是"冷启动 LLM"本身**，而是
"**同款 LLM + 整讲直灌 + 范围约束**"。
**2026-09-26 已补上真正的零约束条件 `raw`**（见上表与 `docs/12` §六）。

**为什么还是这么定**（用户 2026-09-17 的判断）：把范围约束只给 optimized，
优化版可能**仅因为"写得短"而赢**，就分不出是"讲得好"还是"讲得短"。
两条件共用范围约束 → 范围不是变量，差异仍可归因到讲解方式。

**⚠️ 这条措辞纪律已作废**（2026-09-26，见上节）："优于同款 LLM 冷启动"现在**可以说了**，
依据是 optimized vs raw。要拿到真正的冷启动对比，已由第三方条件 `raw` 完成（**已做**）。

### 输入范围 ≠ 输出范围（用户 2026-09-17 指出）

这两件事**必须分开**，我第一版把它们混成了一件：

| | 是什么 | 本阶段怎么定 |
|---|---|---|
| **输入范围** | 喂给模型多少课件原文 | **整讲直灌**（为了让检索不成为隐藏变量） |
| **输出范围** | 这一次讲多少 | **按学生问的那个点定**，600–800 字，不分章节 |

第一版只有"输入整讲"的设定，模型于是**顺手把整章串了一遍**（1.2k–2.2k 字），
用户明确指出"输出不一定一次要输出完一整章"。
→ 处置：在 prompt 里显式区分两者（`_COMMON_TASK` 里写明"原文不等于你这次要讲的范围"），
并把范围约束抽成两条件共用的 `_SHARED_SCOPE`。

> 注：用户这条指正**恰好属于决策层（L2）**。本阶段只用一句 prompt 约束近似它，
> **没有**去建决策层（那需要知识结构，而「教学卡」仍是**待证明**，`docs/04` §九）。

## 三、读法：A/B 自由切换（2026-09-17 定，2026-09-22 改）

**最初的读法**（用户 2026-09-17 定）：并排两栏各 1.5k–2.2k 字**阅读负担过重**
（用户原话："肯定是太重了"）→ 改为**一次只显示一段**、打完 A 自动换 B、
两段都打完才揭晓。

**改动（用户 2026-09-22）**：
> 「改成 A 和 B 可以通过选择自由切换，这样更好对比」

现在是：

1. 同一题的两个回答被服务端**随机**标为 **A / B**；
2. **顶部有 A / B 页签，任何时刻都能自由切换**——包括还没打分时；
   页签上显示该段的打分状态（`未打分` / `4 分（未保存）` / `✓ 4 分`）；
3. **保存一段的评分后不再强制跳转**（原来会自动换段）。理由：跳转会打断来回对比；
   "哪段还没打"改由**页签上的状态标记**提示；
4. 两段都保存后**自动揭晓**哪个是哪个。

> ⚠️ **这个改动的代价要记明**：盲测性质**变弱了**——现在可以随时翻看另一段再回来打分，
> 所以"读第一段时的判断"可能被第二段影响（锚定）。
> 用户明确选了"更好对比"优先于"更严格盲测"，这是他的项目、他的取舍。
> **但要清楚：本轮之后的评分，其"盲"只保证"不知道哪个是哪个条件"，不保证"没看过另一段"。**

**盲测（A/B 不泄标签）仍是服务端强制的**：

| 泄露点 | 处置 |
|---|---|
| A/B → 条件的映射 | 随机分配，**只存在服务端内存**，`/api/ask` 响应里不含条件名 |
| 错误信息 | 不再下发含条件名的错误串，只下发 `failed_count`；条件名打印到服务端控制台 |
| 打分接口 | 按**槽位**（`slot`）打分；落盘时由服务端还原真实条件 |
| 首页 HTML | 自检断言首页不含条件名 |
| 打分接口 | 按**槽位**（`slot`）打分，前端在整个盲测期间拿不到条件名；落盘时由服务端还原 |

目的：祛除"知道哪个是优化版"带来的预期偏见。**这也意味着 A/B 是随机的，
你不能靠"第一段总是 A"之类的规律猜。**

## 六、实测中发现的两个具体问题（不是猜测，有复现）

### 问题 1：默认检索会漏掉"讲这个概念、但措辞不同"的那一页 ★

对问题「什么是仿射空间？它和向量空间差在哪？」：

- 纯词面检索命中 **p2 / p3 / p4 / p5 / p7**
- **漏掉 p8** —— 而 p8 是全讲**唯一**给出「仿射映射」定义的一页

p8 为什么命不中：它只有 **282 字符**，且通篇写的是 `Affine mapping`，
**不含 `affine space` 字样**。于是出现最糟的情形：
**用户问"仿射空间"，系统恰好不给他"仿射映射"那一段。**

→ **处置**：起步阶段默认改为**整讲直灌**（`whole_lecture=True`）。
L01 全讲仅 13,374 字符（含来源标记），DeepSeek 上下文完全放得下；
两条件共用同一份原文，对比仍然成立。命中页模式保留为可选项。
→ **已写成回归断言**：`smoke_test.py` 断言整讲模式必须包含 `l01-p08`。

> 若将来要把"检索"当作独立变量来研究，再打开命中页模式单独评估。
> 现在不研究检索，**只要求它不成为隐藏变量**。

### 问题 2：同一 prompt 跨轮长度会翻转，且**范围约束收不住** ★

同一问题、同一温度，逐轮实测（字符数）：

| 轮次 | 检索范围 | 范围约束 | baseline | optimized |
|---|---|---|---|---|
| 1 | 命中页 5 页 | 无 | **1901** | **1246** |
| 2 | 命中页 5 页 | 无 | **1289** | **1645** |
| 3 | 整讲 8 页 | 无 | **2209** | **1764** |
| 4 | 整讲 8 页 | 有（600–800 字） | **1176** | **1055** |
| 5 | 整讲 8 页 | 有（收紧措辞） | **1049** | **1888** |
| 6 | 整讲 8 页 | 有（收紧措辞） | **1469** | **1431** |

**两个结论，都要留着**：

1. **长度方向不稳定**：第 1、2 轮方向相反（1901>1246，然后 1289<1645）。
   第 5 轮 optimized（1888）甚至超过 baseline（1049）。
   → **不能用长度当作"讲得好"的代理**。
2. **范围约束是软约束，收不住**：目标是 600–800 字，加了约束后三轮实测仍在
   **1049–1888** 之间，且**跨度比加约束前更大**。
   → 一句 prompt 只能**降低**长度、不能**保证**长度。
   → 但**阅读负担确实降下来了**：单段从"整章串讲"降到 1.0k–1.9k 字符。
   （2026-09-22 起不再是"一次只显示一段"——改为 A/B 自由切换，见 §三。）

> **不要再靠反复改 prompt 去追这个数**：那是拿单次结果过拟合。
> 真要严格控制篇幅，应换确定性手段（如按段落截断 / 生成后校验重写），
> 但那属于**新的一步**，要先证明必要性（错题本 §零）。

**因此本步骤的结论口径（写死，别越界）**：
- 只报**用户的满意度评分**（那是主指标）；
- 若要报任何自动指标（长度、token、结构），**必须同时报跨轮波动**，不能只报点估计；
- **不**用长度当作"讲得好"的代理——长度方向都不稳定。

## 七、目前能看到的方向性观察（**不是结论**）

> 依据：n=6 轮、**未盲评**（跑自检的是我，不是用户）、用户还没读过。
> **只作为待检验的假设**记录，不得写进 prompt 或标准文件。

对「什么是仿射空间」这一问，我读到的 optimized 输出里出现过 baseline 没出现的**元层面解释**：
"为什么这个差别是本质的"整节、边界情形（$\vec{x}_0 \in U$ 时退化为子空间）、
以及"丢原点保方向"的收束（两点之差仍落在 $U$ 内）。

这与 `docs/03` §六 约束 2/3/4 的目标方向一致，但：

- **用户可能根本不关心**——这正是要用户实测来裁决的，不能由我判；
- 我读的是**未盲**的输出，**知道哪个是 optimized**，所以这段观察本身带预期偏见；
- 第 5 轮 optimized 反而最长（1888），说明"讲 why"与"讲得短"之间可能**有张力**——
  这是用户实测里值得盯的一个点。
