# 数学渲染方案（LaTeX → MathML）

> **触发**：用户连续三次反馈同一件事——
> 「代码块和字体等没有做渲染，讲得很割裂让人不舒服」（9-18）
> 「**公式没渲染处理，一堆杂乱的符号根本看不懂**」（9-21）
> 「**没有公式和符号的渲染，看起来很费解**」（9-21）
>
> **用户 2026-09-21 指令**：「先做渲染，记住错题本中说的，**解决任何问题先去找有没有可以复用的东西**。」

---

## 一、先找，不自己造（总原则第 2 条）

| 候选 | 结论 |
|---|---|
| **KaTeX**（事实标准） | ❌ 是 **npm / 浏览器端 JS 库**。本机没有；项目惯例**不引 CDN**。要用就得 vendoring 一整套 JS+字体 |
| **MathJax** | ❌ 同上，体积更大 |
| **`latex2mathml`（PyPI 3.81）** | ✅ **采用**。纯 Python、可离线分发 |
| matplotlib `mathtext` | ❌ 只能出位图/路径，不适合网页文字排版 |
| 自己写渲染器 | ❌ **这就是 M1**（遇到没现成的就自己造）。而且数学排版远不是本项目该做的事 |

**为什么 `latex2mathml` 这条路特别合适**：它输出 **MathML**，
而**现代 Chromium / Edge 已经原生支持 MathML**——
所以在**浏览器侧零依赖**：不用 JS 库、不用下载字体、不用 CDN。

## 三、实现结构

```
讲解正文（含 \(..\)  $$..$$  \[..\]  $..$）
        │
        ▼  app/mathrender.py（服务端）
  ① extract_math  找定界符
  ② latex2mathml  转 MathML
  ③ 正文里换成占位符 ⦁MATH0⦁，附替换表
        │
        ▼  /api/ask 下发 {text_tpl, math:[{token, mathml, ok, tex, block}]}
        │
        ▼  前端 index.html
  ④ 转义**前**保护占位符（否则 MathML 的尖括号会被转义吃掉）
  ⑤ 转义**后**把占位符换回 MathML → 浏览器原生排版
```

### 关键实现细节（都是踩出来的）

1. **必须先"收集全部匹配"再判重叠**，不能按定界符逐类处理。
   否则 `$$...$$` 会被行内 `$...$` 从中间跨过去匹配，块级公式识别失败；
   而且 `$5 到 $10` 这种货币金额会被当成公式。
   解决：全部候选收集后按「起点靠前 → 同起点块级优先 → 更长优先」去重叠。
2. **占位符必须在转义前保护**。前端要先做 HTML 转义防注入，
   而 MathML 本身就是尖括号标签，顺序错了就会被转义成文本，显示成一堆标签。
3. **转换失败不静默**：原样返回 LaTeX 并标 `ok=False`，
   前端渲染成**等宽小字**（可读），**绝不显示成符号汤**。
4. **整行只有一个块级公式时独立成块居中**（矩阵、多行推导需要）。

| 层 | 怎么验 | 现状 |
|---|---|---|
| 单元 | `python app/test_mathrender.py`（定界符 + 假阳性 + 14 类记法 + 占位符安全） | ✅ 全通过 |

| **真实浏览器** | `scripts/ui_regression_test.py` 断言 `#body-A math` 存在、块级独立成块、行内 `\(N\)` 真被替换 | ✅ 全通过 |

真实浏览器那条断言是必须的——接口测试只能证明"下发了 MathML"，
**证明不了浏览器真的渲染出来**。

## 五、已知边界

1. **只做渲染，不校验数学正确性**。公式写错是 MQI 编码 12（四级严重度）的事，不在这一层。
2. **`latex2mathml` 不认的宏会失败**（走等宽降级路线）。目前实测样本里没出现；
   若以后出现，先看是不是可以换成它认的等价写法，**不要自己写转换器**。
3. **行内公式数量可能很大**（一次讲解 50–90 处）。这是模型输出风格导致的
   （把几乎每个符号都套了 `\(...\)`），渲染本身没问题，但**可读性未必更好**——
   是否要在 prompt 里限制"不要把单个字母都包成公式"，**留待用户实测判断**，不擅自改。
