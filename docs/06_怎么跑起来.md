# 怎么跑起来（步骤 1：最小闭环）

> 对应 `docs/00_错题本.md` §四「步骤 1」。本文件只讲**怎么用**，不讲为什么这么做（理由在 `docs/05_最小闭环与基线.md`）。

## 一、它现在能做什么

一次提问 → 从 Lecture 1 取课件原文 → **两个条件同时**生成讲解 → **盲测**读两段 → 各打一个满意度分 → 落盘。

| 条件 | 系统指令 | 含义 |
|---|---|---|
| **baseline** | 只加**范围约束** | 同款 LLM + 整讲直灌 + 输出范围约束 |
| **optimized** | 范围约束 + `docs/03` §六 的 4 条 | 同一份原文 + 讲解方式约束 |

**两条件共用的**：检索器、课件原文、模型、参数、**范围约束**。
**唯一的差异**：那 4 条"怎么讲"的约束。所以两段读起来有差别，只能归因到讲解方式。

> ⚠️ **措辞纪律**：本阶段的基线**不是**"冷启动 LLM 本身"（它也带范围约束），
> 所以结论**不得**说成"优于同款 LLM 冷启动"。理由见 `docs/05` §二。

### 输入范围 ≠ 输出范围

- **输入**：整讲课件原文（8 页 / 13,374 字符）→ 为了让"检索"不成为隐藏变量
- **输出**：只讲你问的那个点，目标 600–800 字 → 不把整章串一遍

## 二、启动（用启动脚本，服务能独立存活）

```powershell
# 启动（若已在跑则不会重复启动）
.\scripts\start_server.ps1
# 等价写法： python scripts\serve.py

# 看状态 / 停止
python scripts\serve.py --status
.\scripts\stop_server.ps1
```

成功后会打印 `✅ 服务已就绪：http://127.0.0.1:5000`。

### ⚠️ 为什么必须用这个脚本启动（两次真实故障换来的）

| 试过的做法 | 结果 |
|---|---|
| 挂成"临时后台任务" | 任务结束就被回收 → **打不开网页** |
| PowerShell `Start-Process` | 子进程**继承了启动命令的输出管道**，命令一超时被强杀，服务跟着死 |
| 前台直接跑 `python app\demo_app.py` | 能跑，但**关掉窗口服务就没了** |

`scripts\serve.py` 用 `DETACHED_PROCESS + CREATE_NEW_PROCESS_GROUP`，
并把 stdout/stderr **直接指向日志文件**（父进程不保留任何管道），所以服务能独立存活——
关掉终端窗口，服务照常在。

### 自检与调试入口

```powershell
Get-Content .env                      # 确认有 DEEPSEEK_API_KEY（只需这一项）
python app\smoke_test.py --no-model   # 不花钱：检索/提示词/接口/落盘/临时素材隔离
python scripts\ui_regression_test.py --headless   # 真实浏览器 UI 回归（33 项）
python app\smoke_test.py              # 含一次真实模型调用（会花钱，也会写 2 条评分记录）
python app\demo_app.py --dry-run      # 前台跑，只做检索、不调模型
python app\demo_app.py --port 5050    # 换端口
```

## 三、怎么用：先选"讲法"，再盲测

**新增：讲法下拉框**（`docs/08` §三）。它决定这一次**讲多全**，**两个条件共用**，所以不参与对照。

| 讲法 | 什么时候用 | 会怎么讲 |
|---|---|---|
| **概览** | 想先要一张地图 | 只给骨架，**600–800 字**，点到为止 |
| **详细** | 这块你不熟，要讲全 | **范围内所有知识点一个不漏**；公式/代码全文给出；代码**逐行注释**；不设字数上限 |
| **追问** | 已经讲过一遍，想追一个点 | 只补问到的那个点，不重复已讲的 |

**详细档里有个"设问"**：它会先自己问一句"为什么这里要取反？"，**紧接着自己回答**——
只是让你跟着想一下，**不会要你作答、不会留空让你填**（这是你要求的，见 `docs/08` §3.2）。

然后读两段讲解。**A / B 可以随时点页签自由切换对比**：

系统把两个回答**随机**标成 **A / B**，**打过分之前不告诉你是哪个条件**。

1. 选好**素材 / 分区 / 讲法**，提问 → 先显示 **A 段**
2. **点顶部 `A` / `B` 页签随时切换**（没打分也能切）——两段来回看着比较
3. 页签上会显示打分状态：`未打分` / `4 分（未保存）` / `✓ 4 分`
4. 每段读完 → 点 1–5 分 → 写一句话原因 → 保存。
   **保存后不会再自动跳走**（跳转会打断对比）；哪段还没打看页签
5. 两段都保存后，界面**自动揭晓** A/B 分别是什么，并列出你给的分

> ⚠️ **别去猜 A 是哪个**。服务端每次提问都重新随机分配，且条件名不在下发数据里
> （连"哪一段生成失败"都只说"有几段失败"），所以猜不出、也不用猜。
>
> ⚠️ **但要知道**：现在能自由来回看，所以"读第一段时的第一印象"可能被第二段影响。
> 这是为了"更好对比"付出的代价（你 2026-09-22 选的）。

**打分只问一件事**：这段讲解让你往前走了一步没有（不是"写得专不专业"）。
原因栏尽量写**具体位置**：

- ✅「p3 那个线性无关的定义直接甩出来，没说为什么需要 λ 全为 0」
- ✅「这段把 kernel 为什么是子空间讲清了，那段只写了定义」
- ❌「写得不好」（无法用于改动）

> ⚠️ 满意度是**产品指标**，按定义主观（`README.md` §二.2）。它**不能**用来声称"讲解质量更高"或"学到了更多"（`docs/03` §四.4）。

## 四、数据落在哪

| 路径 | 内容 |
|---|---|
| `data/ratings.jsonl` | 每行 = 一次评分。含 `ts / trace_id / question / slot / condition / blind / score / reason / model / citations / answer` |
| `POST /api/reveal` | 揭晓 A/B 标签（服务端在打分前后都能给，但界面只在两段都打完后调用） |
| `GET /api/stats` | 只报条数与分布，**不下结论**（零方差的一致率不是证据） |

`answer` 字段把**当时那段讲解原文**一起存了，所以以后回溯不用重跑模型。
`slot` 与 `condition` 都存：`slot` 是当时你看到的代号，`condition` 是真实条件——
两者一起才能在以后检查"盲测是否真的随机"。

## 五、参数（什么时候需要调）

| 控件 | 作用 |
|---|---|
| **范围** | 「整讲（推荐起步）」= 8 页全喂；「仅命中页」= 只喂检索命中的页 + 桥接页 |
| **命中页数** | 仅"仅命中页"模式下生效；整讲模式下自动禁用（免得摆一个假控件） |

- Lecture 1 共 8 页 / 13,008 字符：整讲直灌 = **13,374 字符**（含来源标记）；命中页模式通常 4–5 页、6.6k–8.9k 字符。
- 若某提问该讲的内容没被捞进来 → 在"仅命中页"下把命中页数调大，再看折叠栏确认。

## 六、已知的坑（别踩）

- **`APP_STRIP_OPT=1`**：会把 optimized 那 4 条关掉（两条件变成同一份范围约束）。
  这是**自查开关**，正常跑别设。
- `data/ratings.jsonl` 里会有 `[smoke test]` 字样的记录，来自自检脚本，**不算你的真实评分**；统计时按 `reason` 过滤掉。
- 换讲（比如 L02）目前要改 `app/demo_app.py` 的 lecture 选项和 `search()` 的默认 `lecture`。**先别急着扩**，把 L01 的基线跑出来再说。
- 范围约束是**软约束**：模型可能仍略微超出 600–800 字（实测见 `docs/05` §六）。它降低长度，但不能保证。
