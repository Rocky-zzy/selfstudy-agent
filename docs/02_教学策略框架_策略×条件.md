# "如何教得更好"：教学策略文献提炼与适配框架

> **定位**（2026-09-17 更新）：本文是**阶段二「短期适配」的核心依据**——即"用户注入偏好/反馈（2–3 轮）后，通过条件-策略方式让自学体验贴合该用户"。
>
> ⚠️ **状态：框架有，未验证。** 其中「条件」维度依赖交互中可得的信息，而**开发期只有用户本人一个被试**——条件的可获取性是需要先确认的前提（见 `README.md` §五 未解问题 5）。
> 按总原则，本文内容**不得直接写进代码**，除非先在 `docs/00_错题本.md` §三 把状态改为"有依据"。

**背景**：用户最初的学生画像（情绪×参与×知识）提案被学姐否决；随后要求直接从文献找"如何教得更好"，并指出"求助信号设计起来复杂"。
**本文件结论**：认同"求助信号做画像轴太复杂"；建议**放弃"先分类学生再匹配"的画像路线**，转向 **"策略 × 条件"适配框架**——文献支撑更强、工程更简单、仍保留个性化。

---

## 一、先回应你的两个判断

| 判断 | 我的看法 |
|---|---|
| "求助信号设计起来很复杂" | **认同**。作为**稳定画像轴**它需要：事件顺序日志（先作答还是先求助）→ 你与学姐讨论里已标为"命门问题"；多轮观察才敢定类型；还要区分"要答案/要提示"两种求助。链条太长。 |
| "别被我的调查框住" | **接受**。下面的框架不依赖画像，也不需要先推断学生类型。 |

**但我补一句反驳**：求助行为**不是没用**，只是不该拿来做"人的类型"——把它降级为"**当下情境信号**"（这一次是否求助、求助前是否已尝试）就很简单，而且它只是策略选择的**条件之一**，去掉它框架照样跑。

---

## 二、文献里"教得更好"的实证结论（策略清单）

教学与学习科学的核心结论不是"哪类学生该怎么教"，而是一组**有条件的有效策略**：

| 策略 | 核心结论 | 主要文献 |
|---|---|---|
| **Worked Example（例题示范）** | 新手学新内容时，先看完整例题优于直接解题 | Sweller & Cooper (1985); Sweller (1988) |
| **Expertise Reversal（专长反转）** | 同一支持对新手有效、对进阶者**反而有害** → 支持必须随水平撤除 | Kalyuga et al. (2003) |
| **Guidance Fading（指导撤除）** | 从"完整例题 → 部分完成 → 独立解题"逐步撤除 | Renkl & Atkinson (2003, 2007) |
| **Cognitive Load Theory** | 减少与学习无关的外在负荷；复杂内容要分步 | Sweller (1988, 2011) |
| **Retrieval Practice（提取练习）** | 先回忆/自测，比反复阅读更能长期保持 | Roediger & Karpicke (2006) |
| **Spacing（间隔）** | 分散练习优于集中练习（元分析支持） | Cepeda et al. (2006) |
| **Interleaving（交错）** | 混合不同类型题目优于分块刷题 | Rohrer & Taylor (2007) |
| **Self-Explanation（自我解释）** | 让学习者解释"为什么"，显著促进理解 | Chi et al. (1989, 1994); Bisra et al. (2018) |
| **Feedback（反馈）** | 反馈要回答三问：目标是什么 / 现在在哪 / 下一步怎么走；**任务级**反馈优于自我级 | Hattie & Timperley (2007) |
| **Formative Assessment** | 边学边评、及时调整，优于事后总结性评价 | Black & Wiliam (1998) |
| **Productive Failure（生产性失败）** | 先让学生探索（哪怕失败），再讲解，迁移效果更好 | Kapur (2008, 2014, *Cognitive Science*) |
| **Scaffolding & Fading** | 提供支持并逐步撤除；支持撤除时机是适配的核心 | Wood, Bruner & Ross (1976); Collins et al. |

**关键洞察**：这些策略的效力**全部是有条件的（conditional effectiveness）**——条件不满足时，好策略会变成坏策略（最典型就是 expertise reversal）。

## 三、提炼：**"策略 × 条件"适配框架**

不去推断"学生是什么类型"，而是**看当下可观测的条件，选证据支持的策略**。

### 3.1 四个条件维度（全部可从交互推断，不含"人格/类型"）

| 条件 | 可观测信号 | 说明 |
|---|---|---|
| **C1 当前表现** | 答对/答错、犹豫时长、连续失败次数 | 最直接、最可靠 |
| **C2 内容状态** | 新知识点（首次）vs 已学过（复习） | 由知识图谱/题目标注给出 |
| **C3 交互历史** | 这个知识点此前错过几次、上次用了什么策略、有没有效 | **个性化的来源**（跨会话记忆） |
| **C4 显式请求** | 学生明说"给我提示/直接给答案/解释一下" | 最可靠，无需任何推断 |

### 3.2 条件 → 策略映射（初始版，待实验校正）

| 条件组合 | 推荐策略 | 文献依据 |
|---|---|---|
| C1 答错 + C2 新知识点 | **Worked Example**（给完整例题） | Sweller |
| C1 答错 + C2 已学过 | **Hint / 分步提示**（不直接给答案） | CLT + scaffolding |
| C1 连续失败 ≥2 次 | 降难度 / 拆步骤 / 补前置 | CLT（负荷管理） |
| C1 顺利但过快 | 加 **desirable difficulty**（变式、交错） | Bjork |
| C2 复习场景 | **Retrieval Practice**（先问再讲） | Roediger & Karpicke |
| 多知识点混合 | **Interleaving** + **Spacing** | Rohrer; Cepeda |
| 概念性理解 | **Self-Explanation 提示**（"你为什么这样想？"） | Chi |
| 有稳定错误概念 | 对比/反驳式解释 | 概念转变研究 |
| 需要迁移/深层理解 | **Productive Failure**（先探索再讲） | Kapur |
| 任意有反馈的轮次 | **三问反馈**（目标/现状/下一步），任务级 | Hattie & Timperley |
| C3 显示"上次类似策略无效" | **换一种策略** | 个性化（本项目记忆支撑） |

### 3.3 个性化去哪里了？

不在"学生类型"，而在 **C3 交互历史**：
- 记住"该学生在 X 条件下对 Y 策略反应如何" → 下次优先选有效策略；
- 这正是**学习记忆**（原项目 Memory 能力的平移）：记忆内容从"情感/偏好"变为 **"条件—策略—效果"三元组**；
- 好处：不需要给人贴标签，也避免了画像推断的复杂度与不稳定。

## 四、为什么这比"画像路线"更合适

| 维度 | 画像路线（先分类型再适配） | **策略×条件路线** |
|---|---|---|
| 文献支撑 | 求助倾向/RKL 等有支持但分类本身争议大；学习风格已被证伪 | **每个策略都有强实证**（例题效应、提取练习、专长反转…） |
| 推断复杂度 | 高（需事件顺序、多轮、稳定倾向） | **低**（当下表现/内容/请求都能直接观测） |
| 稳定性 | 类型判断易受单次行为噪声影响 | 条件即取即用，不需要"定人" |
| 可评估性 | 需先验证画像准确率（又是一层不确定） | **直接可评**：给定条件，策略选对了吗？效果如何？ |
| 与你的平台约束 | 需要新增日志/流程（学姐已否决） | **多数条件现有日志就有**（对错、用时、请求） |
| 与项目 Memory 专长 | 存"用户画像" | 存"**条件→策略→效果**"，更可操作 |

## 五、对我们的研究意味着什么

**新主线（个性化自学辅助 Agent）的研究问题可以重写为**：

| # | 问题 | 对比 |
|---|---|---|
| RQ1 | **条件感知的策略选择**能否让回答更"对症/合适"？ | 固定策略（总是解释）vs 条件感知选策略 |
| RQ2 | **交互历史记忆**（条件→策略→效果）能否让策略选择随时间改善？ | 无记忆 vs 有记忆 |
| RQ3 | 这套框架是否改善**学习体验与推进**（且不牺牲内容忠实）？ | 同上 |

**可评估**：策略选择准确率（对照教学法专家 rubric）、同条件不同策略的效果对比、学生体验评分、跨会话的策略适应曲线。

**与同组课程问答系统的边界**：他保证"内容忠实"，我们研究"**在忠实内容之上，何时用哪种讲法**"——维度完全不重叠。

## 六、待定（不急于定）

1. **策略库收敛到几条**：建议先做 4–6 条（Worked Example / Hint / Retrieval Practice / Self-Explanation / Desirable Difficulty / 三问反馈），其余留作扩展；
2. **条件信号的可用性**：需确认平台日志实际有哪些（对错、用时、点击、请求类型、是否跨会话）；
3. **策略选择用规则还是 LLM**：建议先规则（可解释、可审计），LLM 只负责"如何表达"；
4. **是否需要 C4（显式请求）之外的推断**：待实验看收益。
