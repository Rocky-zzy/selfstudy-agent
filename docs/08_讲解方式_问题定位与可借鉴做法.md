# 讲解方式：问题定位与可借鉴的成熟做法

> **触发**：用户 2026-09-19 反馈——「有的问题上差异明显，有的问题上又不一样……这是我的单人审查，
> 所以作为一个因子来考虑就行，它只能说明**有一定问题**和**有提升空间**」，并要求
> ① 找问题可能出在哪 ② 找有没有**可以借鉴的、经过实验验证的**讲解方式。
>
> 本文分两部分：**§一 用现有数据定位问题**（可证伪）、**§二 检索到的成熟做法**（带出处）。
> 按总原则：**§二 的东西在落地前必须先写进 `docs/00` §三 并为每条写明出处**。

---

## §一 问题定位：不是"讲得好不好"，是**用了同一种讲法去干两件不同的事**

### 1.1 数据的形状

8 个问题、16 条评分（`data/ratings.jsonl`，逐字原话见 `docs/07`）：

| # | 提问 | 意图 | 基线 | 优化 | 差 |
|---|---|---|---|---|---|
| 1 | 粗略过一遍 numpy | 概览 | 2 | **4** | +2 |
| 2 | 详细讲集合运算和随机数 | 详细 | **4** | 2 | −2 |
| 3 | 简单说说 Pandas，不懂再细讲 | 概览 | **5** | 4 | −1 |
| 4 | `.loc` 与 `.iloc` 怎么选 | 对比/具体 | 3 | **4** | +1 |
| 5 | 详细讲可视化部分 | 详细 | 3 | 2 | −1 |
| 6 | 讲讲常用图的参数 | 详细 | **4** | **1** | −3 |
| 7 | 简要介绍四类 ML 与工作流 | 概览 | 3 | **4** | +1 |
| 8 | 半监督学习凭什么有效 | 追问 | **4** | 3 | −1 |

**按意图分组，规律干净得出奇**：

- **概览类（1、3、7）**：优化 4 / 4 / 4，基线 2 / 5 / 3 → 优化在概览上**从不低于 4**
- **详细类（2、5、6）**：优化 2 / 2 / 1，基线 4 / 3 / 4 → 优化在详细上**全部输，且最差只有 1 分**

> ⚠️ **措辞纪律**：这是 **n=1 被试、8 个问题、每问只测一次**。**不能**说"优化的讲解质量更差"。
> 但它**足以**支撑一个可证伪的机制假设：**问题出在"范围/密度约束与提问意图不匹配"**。
> 这个假设**可以用下一轮实验直接检验**（见 §三）。

### 1.2 定位到四个具体位置

#### 位置 A：范围约束是**固定**的，但意图是**变化**的 ★主因

现在的约束写死为："只回答所问 + **600–800 字** + **不要分章节**"。
它在"粗略过一遍"上帮了忙（点到为止、有结构），在"详细讲"上则**直接对着干**：

- 用户原话：「既然是要详细讲，你就应该**完全包含课件里的内容，只多不少**」
- 用户原话：「我要求的是详细讲，那你就应该**一页一页的**详细告诉我在说什么。**是不是因为有字数限制**」

用户甚至自己猜到了根因是字数限制——**猜对了**。

> **这就是 `docs/01` §三 里 L2 决策层的缺口**：决定"讲多全"本该是决策层的事，
> 我们现在用一句固定 prompt 代替它，于是它必然在一半的意图上失效。

#### 位置 B：代码讲解方式**整个缺失** ★第二主因

3 个"详细"类问题里有 2 个直接指向代码，而且是最低分：

- 第 6 题（优化 1 分）：「**为什么连代码都不给**，说话很没有逻辑」
- 第 5 题（优化 2 分）：「**代码部分应该要通过注释逐行解释才对**」

**现有约束里没有任何一条关于"怎么讲代码"。** `docs/03` §六 的四条（不重复 / 讲 why /
不止简短 / 给合理性）是**通用散文**的判据，来自数学讲解的编码体系（MQI、Thurm），
**不是为代码设计的**。所以约束越"生效"，模型越倾向于写抽象散文、少给代码。

#### 位置 C：「讲 why」被模型实现成了**堆术语**

- 第 2 题（优化 2 分）：「**太多深入的专业术语**让人读起来阻力很大，**既然我是要详细讲说明我对这两个知识点不熟悉**」

用户的推理很关键：**"要求详细讲"本身就是不熟悉的信号**。
而 MQI 编码 3 要求"讲 why"——模型把"给理由"理解成"用更多抽象名词"，
**不是**用更多结构化步骤。`docs/03` 机制一（认知负荷的 redundancy / coherence）
其实是**反对**这个做法的：术语密度在提高外在负荷。

#### 位置 D：两个"不许悄悄发生"的失败

| 现象 | 证据 | 性质 |
|---|---|---|
| 追问推荐了课件里**没有**的问题 | 第 8 题：「那课件里面没有**你为什么要推荐这个问题**？不过讲得还不错而且也**忠于课件没有瞎编**」 | 约束 4（结尾提议深入方向）没有绑定课件；正文忠于课件、提议不忠于课件 |
| 格式约束有漏 | 第 7 题：「**为什么没有用渲染**，这些公式符号很影响观感」 | 模型未始终把公式/代码放进围栏块，界面渲染器就无从下手 |

#### 位置 E（推断，未验证）：**约束过载**，模型挑最容易执行的遵守

现在一共 **12 条**约束堆在一个 system prompt 里（范围 4 条 + 格式 4 条 + 讲法 4 条），
权重相同。我怀疑模型会优先满足**最具体、最好检查**的那几条（字数、不分章节、格式），
而牺牲"讲透"这个最模糊的目标——**这正好解释了为什么"详细"类全输**。

> ⚠️ 这是**推断**，不是实测。要验证得做消融：去掉字数约束后详细类是否回升。
> 在验证前**不得**当结论使用。

## §二 检索到的成熟做法（带出处）

> 检索词（记录在案，便于复核）：`worked examples effect cognitive load theory programming education`、
> `subgoal labeling worked examples programming`、`self-explanation prompts code comprehension`、
> `instructional explanation quality experiment`、`expertise reversal effect meta-analysis`、
> `parsons problems empirical study`。
> 拿不到原文的（ACM / ScienceDirect / Elsevier 付费墙）**如实标注**，不用二手转引冒充原文。

### 2.1 ★ 最强的证据：**自我解释（self-explanation）**

| 项 | 值 |
|---|---|
| 元分析数 / 研究数 / 被试数 | **4 / 112 / 6,450**，178 个效应量 |
| **加权平均效应量** | **0.55** |
| 出处 | [Visible Learning MetaX: Self explanation](https://www.visiblelearningmetax.com/influences/view/self_explanation) |
| 最大单项 | Bisra, Liu, Nesbit, Salimi & Winne (2018), *Educational Psychology Review*：64 研究 / 5,917 学生 / **ES = 0.55** |
| 数学领域 | Rittle-Johnson, Loehr & Durkin (2017), *ZDM*：26 研究 / **ES = 0.27** |

**做法**：不直接给讲解，而是**要求学习者自己产生解释**（"为什么这一步成立？"），
或**给部分解释、让学习者补全**。

**对本项目的含义（重要）**：我们缺的那个"讲解深度"杠杆，**证据最硬的做法不是"讲得更详细"，
而是"让学习者自己讲"**。这与用户第 2、5 题的抱怨方向一致：
"用文字是很难让人理解实用的代码或者方法含义的"——**光靠堆讲解，边际收益很低**。

> ⚠️ 但这是**产品形态的改动**（从"Agent 讲、学生读"变成"学生讲、Agent 补"），
> 与 `docs/01` 的主场景有出入。**必须用户点头才能动**，不得我单方面改产品。

### 2.2 ★ 正好解释数据分岔：**专长逆转效应（expertise reversal）**

| 项 | 值 |
|---|---|
| 结论 | 对**低先验知识**者有效的教学支持，对**高先验知识**者会变成干扰（甚至有害） |
| 出处 | [A cornerstone of adaptivity – A meta-analysis of the expertise reversal effect (2025)](https://www.sciencedirect.com/science/article/pii/S0959475225000660)；原始效应：Kalyuga 等 |
| 元分析要点 | 平均效应量上，**高先验知识组比低先验知识组更小**（即支持对新手更有用） |
| 获取状态 | ⚠️ **ScienceDirect 403，未取得原文**，只有检索摘要；作为方向依据可以，作为精确数值**不行** |

**为什么它能解释我们的数据**：

| 提问 | 用户的先验知识 | 需要的支持 | 我们实际给的 |
|---|---|---|---|
| 粗略过一遍 | 相对高（只想要地图） | **少**（压缩、结构化） | 给少量 -> ✅ 优化 4 分 |
| 详细讲 | **低**（明确说不熟悉） | **多**（范例、逐行、术语解释） | 给少量 -> ❌ 优化 1–2 分 |

→ **我们在两种意图下给了同一种密度的支持，等于在一个方向上必然逆着效应走。**
这已经把 `docs/03` §二 机制三（"适配学生已有知识"）从"提醒"升级为**主因候选**。

### 2.3 已有原文的：**范例学习（worked examples）** 与子目标标注

| 做法 | 说明 | 出处 / 状态 |
|---|---|---|
| **Worked-Out Examples Principle** | 对新手，**研读完整解出的范例**优于自己解题；应配 **fading**（逐步撤掉步骤） | [Cambridge Handbook of Multimedia Learning, Ch.15](https://www.cambridge.org/core/books/abs/cambridge-handbook-of-multimedia-learning/workedout-examples-principle-in-multimedia-learning/5A8A07C14A2911C49982D19950EF5307)（**仅取得章节目录/摘要，正文付费**） |
| **子目标标注（subgoal labeling）** | 给范例的每一步加上"这一步在达成什么子目标"的标签，显著优于无标签 | [Subgoals, Context, and Worked Examples in Learning Computing Problem Solving (ICER 2015)](https://dl.acm.org/doi/10.1145/2787622.2787733)；[Design and Pilot Testing of Subgoal Labeled Worked Examples for Five Core Concepts in CS1 (2019)](https://dl.acm.org/doi/10.1145/3304221.3319756)（**ACM 403，未取得原文**） |
| **自我解释 + 代码** | 提示学生自我解释能提升代码理解；与"打乱的代码块（mixed-up code）"结合对新手更友好 | [Prompting for Free Self-Explanations Promotes Better Code Comprehension](https://par.nsf.gov/servlets/purl/10311827)；[Enhance Code Understanding through Prompted Self-Explanation with Mixed-Up Code Puzzles](https://par.nsf.gov//servlets/purl/10682655)（**PDF 未能抓取，仅检索摘要**） |
| **手写追踪（hand trace）** | 逐行跟踪变量状态变化的表格法，是 CS 教学的常规做法 | [Hand Trace Instructions (Cal Poly)](http://users.csc.calpoly.edu/~jdalbey/101/Resources/codetrace.html) ⚠️ **教学资料，不是实验证据** |

**对"用户要逐行注释解释代码"的直接支持**：`subgoal labeling`（每步标子目标）
+ `hand trace`（每步的变量状态）合起来，正好是用户第 5 题要的东西：
「代码部分应该要通过**注释逐行解释**才对」。

### 2.4 已有的（`docs/03`）：**认知负荷 / 多媒体原则**

`docs/03` 机制一已经确立了 segmenting / signalling / redundancy / coherence 等，
**不需要重找**。但要补一句：**这些是"减少外在负荷"的卫生条件，不是"增加理解深度"的杠杆**。
我们目前把卫生条件当成了主要目标，这可能是"优化"在详细类上反而更差的原因之一。

### 2.5 检索的边界（M7 纪律）

**只能说：在我检索到的范围内**，没找到"专门为**LLM 生成教学讲解**设计的、经过实验验证的讲解方式"。
最接近的是：
- 上面这些**人类教学**的构念（self-explanation / worked examples / subgoal labeling），
  它们经过实验验证，但**验证对象是教学设计，不是 LLM 输出**；
- `docs/03` §四.3 已有的 Xu 等 (2024)：LLM 装既有编码手册做粗粒度判断 **κ=0.46–0.69**，细码不合格。

**我搜了 6 个词族、跨了 4 个文献族**（认知负荷 / 数学讲解编码 / CS 教育 / 自我解释元分析）。
**存在性否定仍不成立**——只能说"我搜到的范围内没有"。

## §三 已落地（2026-09-19）：讲法三档

用户的定义与授权（逐字）：

> 「**详细讲是要求对我提出的范围内的所有知识点细讲**」
> 「**以你提的知识点为线索、相关的都带上**……**不要超出课件内容，又要包含这个课件中知识点部分的全部内容**」
> 「**你可以引导它自我解释，就是你可以先先问用户，然后你再直接给答案，就是设问，
>   不要要求一定要用户作答，这是增加用户的负担。**」
> 「**不要用一样的问题，我后面会给你别的课件，用新的来测。**」

### 3.1 实现

界面上加了**讲法**下拉框（`brief / detailed / followup`），**两个条件共用**：

| 档 | 内容 | 关键约束 |
|---|---|---|
| **概览** `brief` | 维持原样 | 只给骨架；**600–800 字**（实测在概览类上最好：4/4/4） |
| **详细** `detailed` | 新增 | **范围内一个都不许漏**；**只讲课件里有的**（不许引入课件外内容）；**设问但不要等作答**；**代码逐行注释**（含变量状态）；**不设字数上限** |
| **追问** `followup` | 新增 | 只补问到的点，不重复已讲的 |

**为什么两条件共用**：`detailed` 干的是"范围/密度"，属于决策层。若只给 optimized，
就变成"谁讲得全谁赢"，而不是在比"讲得好不好"。

### 3.2 「设问式自我解释」的依据与**代价**（必须写清）

- **依据**：self-explanation 元分析 4 篇 / **112 研究 / 6,450 学生 / 加权 ES = 0.55**
  （[Visible Learning MetaX](https://www.visiblelearningmetax.com/influences/view/self_explanation)；
  Bisra et al. 2018, *Educational Psychology Review*，单独一篇 64 研究 / ES 0.55）。
- **边界（用户定的）**：**设问，但不要求作答**——避免把负担推给用户。
- ⚠️ **代价**：这不是完整的 self-explanation（那种要求学习者**真的产出**解释）。
  我们只保留了"促发自行组织一遍"的部分。**所以 ES 0.55 不能直接搬到这里当预期收益**，
  只能说"方向上有一致的证据支持"。

### 3.3 实测（真实模型，未截断）

| 问题 | 讲法 | 槽位 A | 槽位 B | 上次同题（brief 档） |
|---|---|---|---|---|
| 常用图的参数（上次优化仅 1 分） | detailed | **4602 字** / 2422 tok | **2773 字** / 1307 tok | 1378 / 1295 字 |
| groupby 怎么运作 | detailed | 2326 字 / 1030 tok | 2089 字 / 1098 tok | — |

四种图/五种图的参数逐个讲、代码逐行解释，`finish_reason=stop`、**无静默截断**。
代价：单次生成从 ~1300 字涨到 2800–4600 字，耗时约 15 秒。

### 3.4 怎么验证（**用新课件、新问题**）

用户已明确：**不要用一样的问题**，后面的课件会换 → 所以：

1. 用户提供**新课件**（按 `docs/09` 的流程接进来）；
2. **概览类**问题：验证没有掉下来（基线对照 4/4/4）；
3. **详细类**问题：验证是否从 1–2 分回升（这是核心假设的直接检验）；
4. 判读规则与"同一个问题重复打分的污点"已在上一轮讨论中写明，保持不变。

### 3.5 仍然未做

- **没有**做"要求用户真的作答"的 self-explanation 交互（用户明确否决：增加负担）；
- **没有**为代码讲解引入 subgoal labeling 的原文依据（ACM 403 未取得，只作方向参考）；
- **没有**动"详细=覆盖全"与"覆盖哪些页"的切分——仍按用户提问的知识点为线索。

## §五 提升方向（2026-09-22 重估，**待用户批准后落地**）

> **触发**：用户 2026-09-22——「这个结果说明了我们的冷启动约束**有一定效果但提升还不够**，
> 你想一想我们**如何提升而不是反复去测**」。
>
> **本文的方法纪律**：本节**不引入任何新的文献主张**——所有依据都来自**已经检索过、已存于项目**的材料
> （`docs/03` 的判据、`docs/12` 的实测、`docs/09` 的提取件）。这是总原则第 2 条的用法：
> **先用手上已有的东西，而不是再去找新的**。

### 5.1 先看清"为什么提升不够"——MQI 给了直接答案

MQI 编码 3（Explanations）的四级里，**Mid 与 High 的分界不是"有没有解释"，而是"解释是不是主要特征"**：

| 级 | 原文 |
|---|---|
| Mid | 两处以上简短解释，**或**一处不止简短但**不是焦点** |
| High | 解释**是这一篇的主要特征**（不必占大部分篇幅） |

实测两轮：基线均值 1.91 / 2.09，优化 2.36 / 2.45 —— **都在 Mid 附近，离 High 有明显距离**。

→ 也就是说，**提升不够的机制是清楚的**：约束让模型"确实给了 why"，但**没让它把 why 组织成主干**。
用户原话正对应这一点：*"点到了，但没讲透"*。

**这个机制指向的是"结构"，不是"再加几条措辞约束"。** 下面按**证据强度**排序，不按我觉得好坏排。

### 5.2 第一梯队：改约束（最便宜，依据最硬，可立刻做）

**这三条恰好都是 MQI 那轮盲评**具体抓到的**问题**，不是我从文献推的。

#### ① 设问必须"有答案、且答案在课件里"

- **问题（实测）**：详细档的"设问"约束产生了**假问题**。
  CNF 那一问里标题是「为什么这里要引入新非终结符？」，紧接着正文说方案**恰恰不引入**、而是消掉 $B$。
  MQI 编码 13 判了不精确；Rubrik 那轮判了 Coherence=No。
- **根因**：约束 10 只要求"设问 + 紧接着自己回答"，**没要求答案与设问一致**。
  模板化生成出"问题 ≠ 答案"的段落。
- **改法**：加两条——(a) 设问必须能被紧随的答案**直接回答**；
  (b) 若该处其实没有"为什么"可讲（例如课件直接给了做法），**就不设问**，改成陈述。
- **代价**：改 prompt 一句话，**零新增成本**。

#### ② 例子必须来自课件；增补例子要标出来

- **问题（实测、我自己核过）**：`.loc/.iloc` 那一问里，优化版用
  「按人口降序排一下，`df.iloc[1]` 就指向另一行」作反例——**反例不成立**，
  课件 p43/p45 的数据 `[39.2, 29.5, 21.7, 19.3]` **本来就是降序**。
- **根因**：约束 9 写的是"只讲课件里有的"，但模型把它理解成**不许讲课件外的知识**，
  于是在"举例说明"时**自己造了个例子**填充。
- **改法**：把约束 9 说细——**例子/反例优先用课件里给的；自己要补的例子必须标注"（补充例子）"，
  且不得改变课件里的数值与顺序**。
- **为什么这条重要**：它同时解决"不忠于课件"和用户抱怨过的"讲得不准"。

#### ③ 术语首次出现要给一句白话

- **问题（实测）**：用户两次反馈"专业术语让人读起来阻力很大"（`docs/07`），
  而 MQI 编码 13 恰好要求**区分日常含义与数学含义**、用非技术语言讲不清就记为不精确。
- **依据**：`docs/09` 提取件里的 L14（**英文术语 + 中文解释**，首次出现给 `**Bias（偏差）**`），
  以及 `docs/03` 机制一（coherence：删掉不必要的负担）。
- **改法**：术语首次出现给"英文（中文）+ 一句它在这门课里指什么"；之后直接用英文。
- **注意**：这**不是**要求降低专业性，只是要求首次出现时落地。

### 5.3 第二梯队：改结构（要动代码，依据是 MQI 的分级逻辑）

#### ④ 让"结构"能承载解释 —— 把"详细"档的产物从"散文"改成"有主干的讲解"

MQI 说 High 的标志是"解释**是主要特征**"。散文体天然做不到这一点——因为**散文没有骨架让人看出哪是主干**。

候选做法（**都属于 `docs/09` 里提取、但尚未落地的 L 项**）：

| 做法 | 来源（已存于项目） | 状态 |
|---|---|---|
| 每个知识点按 `Why → Intuition → 正式定义 → How（逐步，含每步为什么）→ 例子 → 常见坑` 的组织 | `docs/09` L2/L3/L4（采自 L7 案例，用户的判断支持，**非实验结论**） | Ⓒ 待试 |
| 例题给完整流水线：`已知什么 → 求什么 → 用哪个概念 → **为什么用它** → 步骤 → 答案 → 为什么答案合理` | 同上 L2；worked examples 有文献支持（`docs/03` §六） | Ⓑ/Ⓒ |
| 概念之间显式连接 + 易混概念对比 | 同上 L7；`docs/03` §三 指出"联结"维**信度最低但难** | Ⓒ 待试 |

⚠️ **这一梯队必须写明是"按该案例先做一版"**，不能写成"已验证有效"（`docs/09` 的措辞纪律）。

### 5.4 第三梯队：建最小知识结构（最贵，但可能是真正的缺口）

**为什么它排最后却可能最关键**：MQI 的 High 是"解释**是主要特征**"——
这需要模型知道**哪些才值得成为特征**。而我们现在只给它"整讲原文 + 一句'范围内一个都不许漏'"，
**"范围"由模型自己从问题里猜**。

这恰好是用户在 `README` §一 里就定下的**阶段一杠杆②（知识图谱）**，也是 `docs/01` 分层图里
**L0 结构那一格至今空白**的原因。**而且用户已明确"只挑几章强相关的来搭"**——
意思是**本来就该做，只是不该一上来建全课**。

**最小形态**（`docs/04` §三 留下的可复用结论：ITS 主流做法**不是质量量表，而是内容覆盖度**；
AutoTutor 的 curriculum script 是"逐知识点内容工件"的成熟前例）：

```
一章 → 知识点清单（含：它是什么 / 前置关系 / 易错点 / 课件哪几页讲它）
```

**它能带来的直接收益**：
- "范围内一个都不许漏"**从模糊变可执行**（不再靠模型猜"范围"）；
- "讲全"与"讲透"的冲突**在结构层解决**，而不是在 600–800 字那条约束里硬扛；
- MQI 编码 3 想要"解释是主干"这件事，**有了主干才可能做到**。

⚠️ **但它仍是"教学卡"家族，状态在 `docs/04` §九 里是待证明**。
按总原则，**动它之前要先说清"为什么非做不可"**——
而 MQI 的实测正好提供了这个理由：**不建结构，编码 3 卡在 Mid**。

### 5.5 明确**不做**的（防止以"提升"为名走回老路）

| 不做 | 原因 |
|---|---|
| ❌ 自造一套新量规来量提升 | M0 的教训；已有 MQI 可用 |
| ❌ 因为 Rubrik 测不出就改造 Rubrik | 已否决，改造它＝M1（`docs/13` §四） |
| ❌ 上"两段式生成 + critic" | `docs/04` §九 仍是**待证明**；不顺手动它 |
| ❌ 继续调字数/篇幅 | 实测已证**软约束收不住**（`docs/05` §五 问题 2），且不是瓶颈 |
| ❌ 死磕编码 4（Sense-Making） | 它两轮翻转、信度低（`docs/12` §2.3②）；**信度低的维度不做信号** |
| ❌ 为通用性做抽象 | 用户写死"不追求通用" |

### 5.6 落地状态

**✅ 已落地（2026-09-22）：详细档改为教学骨架**
（用户：「我觉得这个肯定是有用的……**以这个为骨架应该是没毛病的**」）。

九个部件（顺序固定，**两条件共用**）：

```
是什么 → 为什么需要它 → 直觉 → 形式表达
      → 怎么做（每步给理由：为什么有这步 / 吃什么 / 吐什么 / 下一步为什么要它）
      → 例子（优先用课件里的）→ 算出来怎么看 → 常见的坑 → 什么时候用 / 不该用
```

刻意保留的既有有效性约束：**范围内一个都不许漏**、**只讲课件里有的**、**代码逐行注释**。

**落地时发现并处理的三件事**（都是核对/实测出来的，不是拍脑袋）：
1. **约束编号撞车**：共用块用到 20，条件专属块又从 13 起，拼起来出现两个"13"。
   → 专属块改 **21–24**；已加自检断言「三档讲法 × 两条件的约束编号必须唯一」。
2. **"设问"被骨架取代，已从详细档移出。**
   原约束 10（设问 + 紧接自答）是照 self-explanation 那套设的，
   但**实测抓到它产生"问题与答案不一致"的段落**（CNF 那问：标题问"为什么要引入新非终结符"，
   正文却说方案恰恰不引入；Rubrik 判 Coherence=No、MQI 判编码 13=1）。
   而骨架里的「**为什么需要它**」与「**每一步为什么**」**本来就是促发自行组织的机制**，
   且是**结构性的、不依赖模板化问句**。→ 详细档不再需要设问；**追问档保留一句**（追问没有骨架可依）。
3. **"逐段讲全" vs 约束"不重复"的潜在冲突**已在 optimized 块显式写明：
   *同一个知识点只走一遍骨架；不同知识点各走一遍，不算重复。*

**真实生成验证**（AIAA 2711 / L01 / 详细档）：

| 槽位 | 篇幅 | token | 是否照骨架走 |
|---|---|---|---|
| A | 3805 字 | 2025 | ✅ 出现「是什么」「为什么需要它」 |
| B | 7426 字 | 3716 | ✅ 同上 |

耗时 19.2 s、无截断。但**注意一个副作用：具体化的骨架把篇幅的组间差拉大了**（3805 vs 7426，近 2 倍）。
用户要的是"讲全"，长本身不是问题；**但下一轮要盯它有没有把"长"变成负担**——
用户此前抱怨过"文字太多反而读不懂"。

### 5.7 落地顺序（一步一停）

**✅ 已落地（2026-09-22）：③ 术语首现给白话**

规则：**`English（中文）` + 一句白话说明它在这门课里指什么**，且**同一个术语全篇只加注一次**。

- **放在"两条件共用"块**，不是只给 optimized：术语密度是**呈现层**问题，
  只给一侧就会变成"谁加注谁赢"（与格式约束同理）。而且用户抱怨术语密度是在 **brief 档**那轮
  （"来给我讲讲这一部分大概说了些什么"给了 2 分），说明它不是详细档独有的问题。
- **实测发现：只说"不要重复解释"不够** —— 模型仍会对同一个词加注两次
  （`constituent（成分）` 出现 2 次）→ 改成"**只加注这一次**"才管住。
  修后实测：A 段 1 处、B 段 4 处，**均无重复**。
- **顺带修掉一个结构性隐患**：约束编号原本手写在各块里，
  每次加一条都要全库排查，而且**不同讲法档的共用块长度不同，专属块的起始号没法写死**
  （出现过 brief 档 `11→22` 的**断号**、以及拼起来有两个 "13" 的**撞号**）。
  改为各块只写 `- ` 占位符、由 `number_constraints()` 在拼装时统一编号 →
  **编号天然连续唯一**，并加了自检断言防止有人又写回去。

### 5.8 ★ 骨架的**用法**修正（2026-09-22，用户指出后查证）

用户原话：

> 「**骨架只是骨架，它需要打磨，不是任何时候都要完整的呈现**，
> 你要学习一下什么时候需要完全呈现，什么时候只需要展现一部分就好。」

**查证结果：用户是对的，我原来的写法是错的。**

| 依据 | 结论 | 对我原写法的含义 |
|---|---|---|
| **专长逆转效应**（Kalyuga 等；[2025 元分析](https://www.sciencedirect.com/science/article/pii/S0959475225000660)） | **教学支持应随先验知识增加而撤除**；对已掌握的人，同样的支持会变成干扰 | ❌ 原写"每段都走一遍"把支持量**固定死了**，正好逆着这条 |
| **worked examples 的 fading**（Atkinson/Renkl；[ERIC EJ1102176](https://files.eric.ed.gov/fulltext/EJ1102176.pdf)） | 支持要**逐步撤掉**，不是一直全给 | 同上 |
| **Mayer 原则的边界条件**（[2025 元分析](https://www.sciencedirect.com/science/article/pii/S1747938X25000673)） | segmenting / pre-training / coherence 的效果**受先验知识调节** | 支持"按需给出"而非"一律给全" |
| **IOED：解释深度错觉**（Rozenblit & Keil；[PLOS 2024 复现](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0297850)） | 讲得**完整**会让人以为自己懂了 | 与我们实测吻合：用户给 5 分的那段，准则判 Reason=No + Conciseness=No（内容不实且啰嗦） |

**改法**：把骨架从"每段都走"改成**按需呈现**——

- **必须写**：是什么（定义/结论）、怎么做（算法/证明/代码/推导时）、为什么需要它（新引入的抽象概念时）
- **按需写**（不需要就跳过，**不留空壳、不写"此处略"**）：
  直觉 / 形式表达 / 例子 / 算出来怎么看 / 常见的坑 / 什么时候用
- **判断标准一句话**：*少了这一段，学生会不会就看不懂、或做不出来？* 会→写，不会→跳过
- 另加两条：**宁可短而全，不要长而空**（只能写出套话的段落说明本来不需要）；
  **复杂内容要再拆**（含多层结构的先讲清每步、再串起来；前置不足用一两句补，但不跑题）

> ⚠️ 一个必须承认的后果：**这条改法依赖"判断这个学生已经会什么"，而这是决策层的事**
> （`docs/01` §三 的 L1 学生状态 + L2 决策）。
> 单靠 prompt 让模型猜"学生会不会"，只是**近似**。真正的解法仍是 5.4 的最小知识结构。
> 本节只做"按内容类型判断"这一层近似（比固定全给好，但不如按人判断）。

### 5.9 下一步：用 Math for AI 测一轮

**这一轮不是为了"再测一次"**，是回答一个具体问题：
**"改这一版能不能把 MQI 编码 3 从 Mid 推到 High？"**

- 推上去了 → 说明瓶颈确实在约束与结构，继续沿骨架打磨；

### 5.10 本节的风险与前提（不得省略）

  **第 2 步的测试就是为了证伪这个假设。**
- **骨架来自 `docs/09` 的 Ⓒ 类**（采自用户给的 L7 案例，用户判断支持、**非实验结论**）。
  落地只写了"先做一版"，**不得表述为"已验证有效"**。
- **MQI 编码 3 的 segment 映射（`docs/refs/MQI判据_原文摘录.md`）仍是我做的、未经验证**，
  所以"卡在 Mid"这个判断本身带映射误差。
