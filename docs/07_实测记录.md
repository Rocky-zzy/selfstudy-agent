## 一、故障：第二次提问后按钮失效 ★已修复

**现象**：第二次提问后点"保存评分并换到另一段"，界面卡住、不跳 B 段。

**排查**：服务端日志显示 `/api/rate`、`/api/reveal` 全是 200 → 问题在**前端状态**。
用真实浏览器（Edge）驱动复现，拿到铁证：

```
[第二次提问后] saved: {}  但  saveBtnA_disabled: true, saveBtnB_disabled: true
```

**根因**：`rate()` 把保存按钮设为 `disabled = true`；下一轮 `ask()` 只清了
`state.saved` / `state.scores`，**没有复位按钮**。于是新一轮两个按钮都是灰的，
点了没反应，永远跳不到另一段。

**为什么之前的测试没抓到**：`smoke_test.py` 测的是接口（全 200，正常），
单测测的是后端逻辑。**这类"跨轮没复位的 UI 状态"只有真实 DOM 能看见。**

**修复**：
1. 保存按钮状态收敛到**唯一入口** `setSaveState(slot, ready|busy|saved|failed)`，
   杜绝"某条代码路径忘了复位"。
2. `ask()` 开头显式把两个按钮复位成 `ready`。
3. `reveal()` 不再重复写按钮状态。

**已固化为回归测试**：`scripts/ui_regression_test.py`（真实浏览器，33 项断言），
其中专门有一条复现原故障场景："第二次提问后两个保存按钮都可用"。
可单独跑：`python scripts\ui_regression_test.py --headless`。

## 二、格式：代码块没渲染 ★已修复

**用户原话**：「代码块和字体等没有做渲染，讲得很割裂让人不舒服」。

**处置**（两处，都不涉及"教学质量"主张）：

| 层面 | 做什么 | 性质 |
|---|---|---|
| 界面 | 加轻量 markdown 渲染：围栏代码块 → `<pre>` 深色底、行内代码 → `<code>`、标题/列表结构化。**不引 CDN**，离线可用 | 可用性修复 |
| prompt | 两条件**共用**"输出格式"约束：代码必须放进围栏代码块、行内代码用反引号、不要拼表格 | 中性约束 |

**为什么两条件共用**：格式是**呈现层**，两条件都受影响。
若只给 optimized，就变成"谁格式好谁赢"，而不是在比"怎么讲"。
另外加了「看原文」开关，可以随时核对模型到底写了什么（渲染不影响落盘与评分）。

## 三、范围：与「详细讲」直接冲突 ★未定，是下一步的输入

**用户原话**：「既然是要详细讲，你就应该**完全包含课件里的内容，只多不少**」。

**我的解读（待用户确认，不得当结论）**：用户要的"详细"≠ 讲得长，而是
**覆盖要全**——课件的相关公式/代码/步骤一个都不能少。而当前范围约束写的是
"只回答所问 + 600–800 字 + 不分章节"，**恰好与之相反**。

**注意这里有个张力**（不是矛盾，是同一约束在不同意图下效果相反）：

| 提问意图 | 范围约束的效果 |
|---|---|
| "粗略过一遍" | ✅ 帮助大：点到为止、有结构 → optimized 4 分 |
| "详细讲" | ❌ 有害：该给全的内容被砍了 → optimized 2 分 |

→ **范围约束不该是固定字数，而应跟着意图走**（这正是决策层 L2 的事）。
但**现在只有 2 个问题、1 个被试**，不足以定规则（错题本 M6）。
**下一步需要更多"详细讲"的样本**，再决定是否把"详细"映射成"覆盖更全"。

## 四、术语密度：与"不熟悉"矛盾 ★未定

**用户原话**：「太多深入的专业术语让人读起来阻力很大，**既然我是要详细讲说明我对这两个知识点不熟悉**」。

**我的解读（待用户确认）**：用户的推理是——**会要求"详细讲"本身就是不熟悉的信号**。
所以对不熟悉的内容，"讲 why"若靠堆术语来实现，反而**加重**理解负担。

**这与 `docs/03` §六 约束 2/3/4 有张力**：MQI 编码 3 要求"讲 why"，
Thurm C1 要求"不止简短的、涉及含义的解释"——但**没有一条说要用更多术语**。
`docs/03` 机制一（CLT 的 coherence / redundancy）其实支持"删掉不必要的负担"。
→ 所以更可能是**我落地约束的方式**（用术语密度换"深度"）走了样，
而不是约束本身错。**要用更多样本确认，不能现在就改。**

## 五、这一轮不能得出的结论（写死，防越界）

- ❌ 不能说"optimized 更好/更差"：**2 个问题、方向相反**，n=1 被试。
- ❌ 不能用字数解释分数：第 3、4 条字数几乎相同（1523 / 1624），分数却是 4 / 2。
- ❌ 不能声称"满意度提升"：主指标目前只有 4 条记录。
- ✅ 可以说的是：**范围约束与意图不匹配**、**术语密度与不熟悉度不匹配**——
  这两条是**有原话支撑的具体机制假设**，值得下一轮专门测。
